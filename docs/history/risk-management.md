# 风险管理笔记

> **Historical / reference.** 保留此前识别的维护风险；不定义当前需求、验收或优先级。当前约束以[系统契约](../current/system-contract.md)和[验证](../current/verification.md)为准。

| 风险 | 触发时机 | 最小应对 |
| --- | --- | --- |
| 特殊协议与部署不兼容 | 修改代理、端口、TLS 或部署方式 | 复核 WebSocket、Trailer 和 HTTP/2 入口。 |
| 改动破坏既有解法 | 修改页面、资源、路由、响应或提示 | 先判断是否为线索；运行相关自动化测试，并复核必要人工链路。 |
| 自动化覆盖留白 | 改动 11、19、21、23 或浏览器依赖能力 | 明确保持、缩小或扩大留白；不要将未测内容表述为已验证。 |
| 测试资源失控 | 新增协议、文件或浏览器测试 | 保留超时、并发限制、临时目录与 server 清理。 |
| 安全或配置改动误伤玩法 | 改动 Cookie、认证、CSRF、中间件或配置 | 对受影响关卡增加定向回归。 |
| 会话或状态文件不一致 | 改动 25、26 关状态模型或存储 | 验证会话隔离、读写、业务失败与 solved/flag 路径。 |
| 单人维护导致事项堆积 | 新增较大范围工作 | 维持小步改动；只将已确定行为写入当前规范。 |

不定期更新关卡、架构或测试方式时，优先检查相关风险；不需要为此维护独立计划流程。
