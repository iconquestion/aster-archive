# 测试改进备忘

> **Historical / reference.** 保留此前的可选测试方向；不改变当前验证范围或验收要求。当前事实以[验证](../current/verification.md)为准。

| 方向 | 解决的留白 | 价值与成本 |
| --- | --- | --- |
| 浏览器自动化 | 11、19、23 关，以及 Service Worker 和页面运行时行为 | 收益高；需维护浏览器环境并谨慎处理反调试玩法。 |
| HTTP/2 专项客户端测试 | 21 关的 `103 Early Hints` 与 stream 行为 | 收益中等；实现和调试成本高于普通 HTTP 测试。 |
| 人工回归清单 | 已知但不适合自动化的玩法 | 收益稳定、成本低；应保持简短并链接到验证证据。 |
| 关卡级测试矩阵 | 自动化、人工验证和明确留白之间的可见性 | 成本低；仅在现有验证文档不足以快速定位时添加。 |
| 安全回归分组 | Cookie、CSRF、认证和会话隔离 | 成本低；适合在相关依赖或中间件变化时使用。 |
| 少量端到端烟雾测试 | 首页可达、关键入口和部署后连通性 | 可发现高影响断链；不要追求全关卡自动通关。 |

## 采用原则

- 先解决明确的验证痛点，再引入工具。
- 不以覆盖率数字为目标；测试应保护真实玩法和稳定运行。
- 新增自动化能力后，更新[验证](../current/verification.md)，不要在本文件中复制当前覆盖结论。
