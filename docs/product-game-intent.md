# 产品与关卡意图

**状态：当前产品规范。** 本文件定义玩家体验与关卡设计意图；接口、状态码和部署约束以[系统契约](./system-contract.md)为准。

## 项目与边界

`Aster Archive` 是一款以网页、请求和协议行为为线索载体的 Web 解谜游戏。目标玩家具备基础 Web/HTTP 认知，并愿意使用浏览器开发者工具探索。玩家从起始页出发，通过真实可观察的页面、资源、请求或协议线索取得下一关入口。

当前文档覆盖已实现的 `01`–`26` 关。关卡不按阶段划分，而是持续、不定期更新；第 26 关之后的入口属于同一持续更新的主线。

产品约束：线索必须真实存在于玩家可观察的系统层；关卡应提供足以开始探索的题面或提示；特殊协议应让玩家实际接触，而非仅以模拟文本替代；关卡之间不应意外共享玩家状态。档案馆叙事应服务探索感，而不是遮蔽必要规则。

## 关卡意图（唯一当前来源）

| 关卡 | 玩家应理解／体验的核心机制                             |
| ---- | ------------------------------------------------------ |
| 01   | 查看页面源代码。                                       |
| 02   | 检查被引用的资源文件。                                 |
| 03   | 检查 `<head>` 元数据。                                 |
| 04   | 观察 HTTP 响应头。                                     |
| 05   | 使用不同 HTTP 方法。                                   |
| 06   | 对比修改查询参数前后的身份反馈。                       |
| 07   | 沿用查询参数中的地点命名规律，查找导览外的地点。       |
| 08   | 从关卡的 `robots.txt` 找到书库，并沿目录索引找到卷宗。 |
| 09   | 按静态资源命名规律寻找旧版本。                         |
| 10   | 阅读 JavaScript 中的余数校验，填入数字并重新排列照片。 |
| 11   | 按顺序处理多层编码与文本变换。                         |
| 12   | 在售货机找到隐藏入口，登录后查询房间配送信息。         |
| 13   | 比对展厅目录与 `sitemap.xml`，找到未直链的展品草稿。   |
| 14   | 根据门禁的响应头识别接口要求的认证方式。               |
| 15   | 通过 WebSocket 反馈推进迷宫状态。                      |
| 16   | 观察 `Referer` 来源 URL 的参数如何影响服务端反馈。     |
| 17   | 在 HTTP Trailer 中寻找响应结束后的信息。               |
| 18   | 用 Range 请求拼接分段内容。                            |
| 19   | 区分页面显示与源文本，并利用字体映射。                 |
| 20   | 用接口反馈逐步缩小猜测范围。                           |
| 21   | 观察 HTTP/2 的 `103 Early Hints` 并追踪预提示资源。    |
| 22   | 修改 `Accept-Language` 触发语言协商分支。              |
| 23   | 绕过前端反调试干扰后从 `localStorage` 取得结果。       |
| 24   | 将 RSS/Feed 视为站点内容线索。                         |
| 25   | 观察 Service Worker 的离线保护、快照与恢复流程。       |
| 26   | 通过会话内水管棋盘的放置、旋转和库存规则完成连通。     |

完整通关步骤、答案和历史实现说明在[题解参考](./reference/level-solutions.md)中；它不定义上述意图，也不替代系统契约。第 26 关题解尚待补充。
