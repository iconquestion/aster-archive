# 系统契约

本文定义首页、起始页、更新页和第 01–26 关的接口、协议、会话与运行要求。新增关卡或运行能力前，应补齐相应契约。契约变更由维护者确认，当前实现与目标的差异记录在文末。 [产品与关卡意图](./product-game-intent.md) · [维护指南](./maintenance.md)

## 站点与通用规则

- `/` 展示项目定位、开放进度和游戏入口，`/00-letsstart` 说明玩法、flag 和必要约定，`/updates` 记录公开进度。
- 第 01–26 关构成连续主线，每关都须提供通往下一关的线索。flag 使用两位关卡编号和十位路径标识，当前的标识由小写字母和数字构成。服务应统一提供页面和静态资源，玩家能在页面、资源或协议行为中观察到实际线索。
- 关卡页面应提供标题、题面和提示入口。例外规则、额外操作前提或特殊访问方式须在题面或公开说明中交代，缺少独立提示时应说明替代方式。首页、起始页、关卡页和限制访问材料的命名、叙事与开放进度应一致。首页、起始页和低风险页面应具备基础响应式布局，结果区应避免明显布局跳动。
- 后端关卡优先使用 `/api/{关卡编号}/…`。默认允许游客通过 HTTP/1.1 访问，另有协议或会话要求时以具体接口为准。JSON 写接口默认接收 `application/json`，表单登录也可接收 `application/x-www-form-urlencoded`。
- 服务须校验路径参数、查询参数、请求体和 Cookie 等客户端输入。关卡依赖时间、语言或请求头时，判定条件和可见反馈应一致。对相同条件，线索依赖的响应头、响应体、Cookie 和状态码应能稳定复现。
- JSON 响应默认用 `application/json; charset=utf-8`。缺参、类型错误或坐标无效通常返回 `400`，认证或授权失败返回 `401` 或 `403`，路径不存在返回 `404`，方法不允许返回 `405`。合法请求未满足谜题规则时可返回 `200` 和可理解的业务失败信息。未处理的异常返回 `500` 和通用错误消息，内部路径和配置细节只供服务端记录。

这些接口不写入状态文件。第 12 关登录会签发 Cookie，并可在进程内缓存当日口令。

| `GET /api/04`               | 无                                                              | `200`，JSON 至少含 `message`，响应头 `X-Archive-Next` 包含下一关线索。                                                                                          |

## 特殊协议接口

玩家必须能通过实际协议观察线索。反向代理无法稳定转发所需行为时，部署须提供对应的直连入口。

### `WS /api/15/challenge`

- WebSocket 升级成功后发送欢迎消息。首次发送 `{"action":"init"}` 会开始第 1 张迷宫，随后重复发送仅返回当前状态。初始化和进入下一张迷宫时返回编号 `stage`、总数 `stage_count`、宽高 `x` 和 `y`、`current_location` 以及 `view`。
- 三张迷宫按 7×7、13×13、20×20 推进。尺寸均包含固定的一圈外墙，起点和出口都在墙圈内。
- `move` 接受 `direction` 为 `up`、`down`、`left`、`right`。每次返回 `success`、`wall`（`1` 为撞墙，`0` 为走通）、`win`、`current_location` 和 `view`。撞墙时坐标与视野保持原值。
- `current_location` 是服务端保存的零基 `{x, y}` 坐标。`view` 是以当前位置为中心的 3×3 数组，按从上到下、从左到右排列。格子值 `0` 表示路，`1` 表示墙，`"S"` 表示起点，`"E"` 表示出口。
- 到达本张出口后，响应附带本张完整 `maze` 和 `flag`。前两张的 `complete` 为 `false`，须在同一连接发送 `{"action":"next","flag":"<当前 flag>"}` 才能进入下一张。完成第三张时 `complete` 为 `true`，返回第 16 关的 `flag` 后关闭连接。
- 非法 JSON、非法动作、未初始化时移动、非法方向和无效的阶段切换都返回结构化错误。服务端用 WebSocket 心跳维持连接，请求最多 4 KiB。进度按连接隔离，重新连接从第一张开始。

### `GET /api/17`

玩家通过 HTTPS 访问。返回 `200` 和 JSON 正文，响应头声明 `Trailer`，响应结束时附加包含第 18 关线索的 Trailer。

### `GET /api/21` 与 `GET /api/analytics.js`

- 两条路径由同一独立 HTTP/2 服务提供。`/api/21` 在正式 `200` JSON 响应前发送 `103 Early Hints`，其中的 `Link` 为 `<analytics.js>; rel=preload; as=script`。正式响应含 `message`，并应允许站点主入口跨源读取。
- `/api/analytics.js` 返回 `200` 和 JavaScript 内容，提供第 22 关线索。
- 独立服务对未知路径返回 `404`，对不允许的方法返回 `405`，未处理异常返回 `500`。

## 会话与存档

第 25、26 关的系统签发会话标识是 32 位十六进制字符串，Cookie 为 `HttpOnly`、`SameSite=Lax`。服务端校验标识后，将每个会话映射到服务端受控目录内独立、可读的 JSON 文件。有效会话重复访问时复用原状态。文件缺失、损坏或过期时，按关卡规则返回错误或建立新会话，各玩家状态必须隔离。

### 第 25 关 · 运维终端

状态至少包含字符串 `field`、`current_value`、`updated_at`，以及可选对象 `last_recovery`。`updated_at` 使用可序列化的时间格式。服务应在处理请求时顺带清理过期文件，单个文件清理失败时继续处理当前请求。除登录外，以下接口都要求有效 Cookie，缺失、格式错误或对应文件不可用时返回 `401`。

| 接口                            | 输入                                                                                                                               | `200` 响应与副作用                                                                                          |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `POST /api/25/login`            | `username: string`、`password: string`。凭据不符合本关规则时返回 `401`。                                                           | 至少返回 `message`、`field`、`current_value`、`updated_at`，签发新 Cookie 并创建状态文件。                  |
| `GET /api/25/state`             | 有效会话 Cookie                                                                                                                    | 返回当前状态对象。                                                                                          |
| `GET /api/25/snapshot-template` | 有效会话 Cookie                                                                                                                    | 至少返回 `field`、`snapshot_id`。                                                                           |
| `POST /api/25/commit`           | `new_value` 为非空字符串，缺失时返回 `400`。                                                                                       | 至少返回 `message`、`field`、`current_value`、`updated_at`，并更新当前会话文件。                            |
| `POST /api/25/recover`          | 必填字符串 `old_value`、`new_value`、`modified_at`、`snapshot_id`，缺字段时返回 `400`。可选 `field: string` 缺失时可使用默认字段。 | 至少返回 `message`、`field`、`current_value`、`updated_at`、`snapshot_id`，并写回恢复后的值和最近恢复记录。 |

### 第 26 关 · 水管棋盘

每个会话保存 `width`、`height`、`source`、`targets`、`cells`、`inventory` 和 `solved`。棋盘固定为 10 × 10，起点和各终点用 `{x,y}` 表示，`cells` 为二维格子数组。库存 `inventory` 记录每种水管的数量。

- `tileType` 支持 `empty`、`source`、`target`、`blocker` 和 `pipe`。水管格包含 `pipeType` 与 `rotation`，可带 `locked`。型号为 `straight`、`elbow` 或 `tee`，方向为 `0`、`90`、`180` 或 `270`。锁定水管和障碍格不可修改。
- 棋盘写操作须重新计算并保存 `solved`。仅当所有终点都与起点连通时，`solved` 才为 `true`。
- 除取旗外，响应优先返回布尔值 `success`、可读字符串 `message` 和布尔值 `solved`。格子操作的 `x`、`y` 均为从 `0` 到 `9` 的整数。坐标、型号或方向非法时返回 `400`。库存不足、格子状态不符或格子只读时，返回 `200`、`success: false` 和能区分原因的消息。
- 首次读取棋盘或旧会话失效时建立新会话。除取旗外，其他接口在缺少有效会话时也可自动建立会话。

| 接口                         | 成功响应与状态变化                                                                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/26/board`          | `200`。在通用响应字段之外返回序列化 `board` 和 `inventory`，写入或续写 Cookie。无有效会话时创建状态文件。                                                   |
| `GET /api/26/flag`           | 有效且已通关的会话返回 `200` 和 `{"success":true,"message":"<next-flag>"}`，可续写 Cookie，谜题状态保持原值。会话无效、状态文件缺失或尚未通关时返回 `403`。 |
| `POST /api/26/reset`         | `200`，返回通用响应字段，用新棋盘覆盖当前会话文件。                                                                                                         |
| `PUT /api/26/tiles/:x/:y`    | 请求体含 `pipeType` 和 `rotation`。空格和库存都满足条件时放置水管，扣减库存并落盘。成功返回 `200`、`success: true` 和最新 `solved`。                        |
| `PATCH /api/26/tiles/:x/:y`  | 请求体使用 `rotation`，忽略额外字段。仅更新已有玩家水管的方向并落盘，库存保持原值。成功返回 `200`、`success: true` 和最新 `solved`。                        |
| `DELETE /api/26/tiles/:x/:y` | 删除已有玩家水管、返还库存并落盘。成功返回 `200`、`success: true` 和最新 `solved`。                                                                         |

## 运行与验收

- 部署以单机运行为前提。代码、静态资源、测试和文档分开放置，后端按关卡划分，存档业务规则应便于追踪。站点应让玩家通过现代浏览器和必要的协议工具完成主线。
- 统一加载并校验 HTTP、HTTPS、HTTP/2 端口、站点来源和 TLS 配置。必需配置缺失、非法或冲突时须在启动阶段显式失败。应用须支持可配置的日志和按日轮转，并应支持优雅停机。服务和部署应采用与关卡意图相符的安全默认值。
- `npm test` 是统一自动化入口。首页、起始页、更新页、主线连通性、健康检查、关键 HTTP 行为、日志初始化、第 15、17 关的协议行为，以及第 25、26 关的会话、持久化和主要失败分支须纳入回归测试。
- 验收还须确认主线可连续推进，部署入口能访问第 15、17、21 关所需的协议，浏览器相关玩法和题面提示可用。维护者或指定验收人员记录日期、环境、入口、步骤及结果，并跟进失败项。 [验证步骤](./maintenance.md)

## 待修的实现差异

- **请求方法。** 普通关卡缺少统一的 `405` 处理，部分不受支持的方法会落到默认的 `404`。 [应用装配](../src/app.js)
- **配置冲突。** 契约要求在启动阶段显式失败。目前监听端口冲突由服务记录错误，其他监听器可以继续运行。 [监听服务](../src/createServers.js)
- **第 17 关 HTTPS。** 契约要求玩家通过 HTTPS 访问。当前普通 HTTP 和 HTTPS 监听器共用带有该路由的 Express 应用，部署入口的访问方式仍需核对。 [监听服务](../src/createServers.js)
- **第 18 关 Range。** 若起点有效但终点超出文本长度，当前实现先把终点截到末尾，再按实际长度判断是否返回 `206`。契约要求越界返回 `416`。 [Range 路由](../src/levels/18.js)
- **第 20、25 关字段类型。** 部分契约规定的字符串字段在实现中先转成字符串，再检查是否为空。 [猜测接口](../src/levels/20.js) · [终端接口](../src/levels/25.js)
